## 0. 项目概述

### 0.1 目标
帮助大学生更高效地找工作：聚合每日企业招聘信息、AI 定制简历、面试技巧题库、行业分析职业规划，并以访客反馈驱动持续迭代。

### 0.2 目标用户与规模
- **校园社区公开服务**：面向本校及若干高校学生，百人~千人量级
- 需要登录注册、高校认证

### 0.3 已确认决策汇总

| 维度 | 决策 |
|------|------|
| 目标规模 | 校园社区公开服务（百人-千人） |
| 技术栈 | Python(FastAPI) + Vue3 + TypeScript + PostgreSQL |
| 预算 | 零成本基础架构 + 可接受少量 AI 付费（DeepSeek） |
| 登录 | 邮箱 + 教育邮箱验证 + GitHub/QQ OAuth |
| 数据源 | GitHub 开源校招仓库 + 企业官网爬虫 |
| 架构 | 单体 + GitHub Actions 定时爬虫 |

## 3. 数据模型（PostgreSQL）

共 11 张核心表：

```sql
-- 用户与认证
users (id, email, password_hash, nickname, role,
       oauth_provider, oauth_id, created_at)
       -- role: user / verified_student / admin

user_profiles (user_id, edu_email, edu_verified, school, major,
       graduation_year, phone, bio, avatar_url,
       skills[], experience_json, projects_json,
       updated_at)
       -- experience/projects 存 JSON 便于 AI 生成简历

oauth_accounts (id, user_id, provider, provider_uid, created_at)

-- 岗位
jobs (id, title, company, company_type,  -- 国企/民企/外企/事业单位
      location, salary_min, salary_max, salary_unit,
      start_date, end_date,            -- 开始/截止时间
      job_category,                    -- 技术/产品/运营/金融/...
      job_type,                        -- 校招/实习/社招
      degree_required,                 -- 本科/硕士/博士
      description_html, source_url,
      source_repo,                     -- 来自哪个 GitHub 仓库
      raw_data_json,                   -- 原始数据留底
      is_active, created_at, updated_at)

job_tags (id, job_id, tag)              -- 多标签：六险一金/解决户口/...

favorites (id, user_id, job_id, note, created_at)

-- 简历
resumes (id, user_id, target_job_id,
         customized_content_json,  -- AI 生成的定制内容
         pdf_url, version, created_at)

-- 面试与题库
interview_tips (id, job_category, content_markdown,
                updated_at)        -- 按岗位类别缓存

question_bank (id, job_category, question, answer,
               question_type,      -- 笔试/面试/HR面
               difficulty, source, updated_at)

-- 反馈与日志
feedback (id, user_id, category, content,
          status, admin_reply, created_at)

visit_logs (id, user_id, path, ip_hash,
            user_agent, created_at)  -- 访问记录
```

**关键索引**：
- `jobs(end_date)` 按截止时间排序
- `jobs(company_type, job_category)` 筛选
- `favorites(user_id, job_id)` 唯一约束防重复收藏

## 4. 认证系统

### 4.1 流程

```
注册：
  邮箱 + 密码 → 发验证邮件 → 验证通过 → 创建 user
  ↓（可选）
  绑定教育邮箱（@xxx.edu.cn）→ 发验证邮件 → 标记 edu_verified=true
  → 自动升级 role=verified_student（可看到认证专属内容）

登录方式：
  1. 邮箱密码登录
  2. GitHub OAuth（免费，学生基本都有）
  3. QQ OAuth（免费，国内用户友好）

JWT Token：
  - access_token (30 分钟)
  - refresh_token (7 天)
  - 存 httpOnly cookie 防 XSS
```

### 4.2 高校认证策略（零成本）

- **主方案**：教育邮箱后缀白名单（`@xxx.edu.cn`）+ 邮件验证码
- 维护一份 `edu_domains.csv`（学校 → 邮箱后缀映射，开源数据集可找到）
- 学生填学校名 → 自动匹配后缀 → 输入教育邮箱 → 收验证邮件 → 通过
- 不依赖教务系统（接口封闭、需学校合作），教育邮箱已足够证明学生身份
- **兜底**：无教育邮箱的学生上传学生证 → 管理员人工审核（后台批量处理）

### 4.3 OAuth 接入要点
- GitHub OAuth App：免费创建，回调拿 token
- QQ 互联：需实名 + 个人开发者审核，免费但有审核周期
- 用 `authlib` 库统一处理 OAuth 流程

## 5. 爬虫子系统

### 5.1 架构

```
┌──────────────────────────────────────────┐
│ GitHub Actions (.github/workflows/)       │
│  - schedule: "0 0 * * *"  (UTC 0点=北京8点)│
│  - 手动触发: workflow_dispatch             │
└─────────────────┬────────────────────────┘
                  │
      ┌───────────▼────────────┐
      │ Python 爬虫脚本          │
      │ 1. 拉取 GitHub 校招仓库  │
      │ 2. 爬取企业官网列表       │
      │ 3. 清洗 + 分类 + 去重     │
      │ 4. AI 辅助分类（国企/民企）│
      └───────────┬────────────┘
                  │
      ┌───────────▼────────────┐
      │ 写入 Supabase PostgreSQL │
      │ + 提交日志到仓库          │
      └────────────────────────┘
```

### 5.2 主力数据源（GitHub 开源校招仓库）

| 仓库名 | 内容 | 数据格式 |
|--------|------|----------|
| `NowPull/CampusRecruitment` | 互联网校招信息聚合 | JSON/Markdown |
| `wfcnhr/2024-campus` | 2024 校招汇总 | Markdown |
| `Internship52/CampusRecruitment` | 实习+校招 | JSON |
| `OfferBring/Campus-Jobs` | 校招岗位列表 | Markdown |
| `campus-recruitment` 系列仓库 | 各年度校招 | YAML/JSON |

> 注：仓库地址需在实施时实际搜索确认（GitHub 上这类仓库每年都在更新），用 `gh search repos` 找最新的。

### 5.3 企业官网爬虫适配器（Adapter 模式）

每个企业一个适配器，统一接口：

```python
class BaseCompanyAdapter:
    company_name: str
    company_type: str  # 国企/民企/外企
    careers_url: str

    def fetch_jobs(self) -> list[JobRaw]: ...
    def parse_detail(self, url: str) -> JobDetail: ...
```

优先适配：
- 互联网大厂（字节/阿里/腾讯/美团/百度）
- 国企央企（中烟/国家电网/三大运营商）
- 银行（四大行+股份制）
- 热门外企（微软/谷歌/英特尔）

### 5.4 数据清洗与分类

- **去重**：`hash(title + company + location)` 作为唯一键
- **字段抽取**：用正则 + AI 兜底抽取薪资范围、截止时间
- **企业类型识别**：维护 `companies.csv`（公司名 → 国企/民企/外企/事业单位），AI 补充未知公司
- **截止时间解析**：`dateparser` 库处理"尽快"、"2025年10月"、"10月底"等中文表达

## 6. AI 子系统

### 6.1 三个 AI 功能模块

**1. 简历定制生成**

```
输入：user_profiles.experience_json + projects_json + skills[]
      + 目标岗位 job.description_html
处理：
  - Prompt 模板提取岗位关键能力词
  - RAG：从用户经历中检索最相关项目
  - DeepSeek 生成定制简历内容（突出匹配点）
输出：resumes.customized_content_json（基本信息/教育/项目/技能/自我评价）
      → 渲染 HTML → wkhtmltopdf 转 PDF → 存对象存储/本地
```

**2. 面试/笔试技巧**

```
输入：favorites 中的岗位 → job_category
处理：
  - 按岗位类别预生成技巧缓存到 interview_tips 表
  - 笔试题库：爬牛客/力扣讨论区公开题（注意版权）+ AI 生成模拟题
  - 每周定时刷新
输出：每个岗位类别一套技巧 + 题库
```

**3. 行业分析 + 职业规划**

```
输入：用户专业 + 当前所有岗位数据聚合
处理：
  - 统计：各行业岗位数、薪资分布、地域分布、企业类型分布
  - ECharts 前端可视化
  - AI 生成"专业→行业匹配"建议（结合行业趋势）
输出：
  - 行业仪表盘（前端图表）
  - 个人职业规划报告（AI 生成 Markdown）
```

### 6.2 AI 调用成本控制

- DeepSeek-Chat 价格约 1元/百万 tokens，单次简历生成 ~2000 tokens = ¥0.002
- 缓存策略：相同岗位类别的技巧/题库只生成一次，每周刷新
- 用户每日 AI 生成次数限制（如 5 次/天）防滥用
- 智谱 GLM 免费额度作为备用，超出预算自动降级

## 9. 部署方案（零成本详细配置）

### 9.1 前端部署（Vercel，免费）
1. GitHub 仓库关联 Vercel
2. 构建命令 `npm run build`，输出目录 `frontend/dist`
3. 自动 HTTPS + 全球 CDN
4. 自定义域名（可选，免费域名可用 `xxx.vercel.app`）
5. 环境变量：`VITE_API_BASE_URL` 指向后端

### 9.2 后端部署（Render / Railway，免费层）
- **Render Web Service**：免费层 512MB RAM，15 分钟无访问会休眠
- **休眠对策**：UptimeRobot 每 10 分钟 ping 一次 `/health` 接口保活
- 或选 **Railway** 试用额度（每月 $5，够用且不休眠）
- 构建：`Dockerfile` + `uvicorn app.main:app --host 0.0.0.0 --port $PORT`

### 9.3 数据库（Supabase，免费层）
- 500MB 存储 + 50MB 连接池，够校园服务用
- 自带 Auth / Storage / Realtime，可省后端工作
- 用连接池 URL（避免连接数超限）

### 9.4 Redis（Upstash，免费层）
- 10000 命令/天，用于：限流、缓存岗位列表、JWT 黑名单

### 9.5 爬虫（GitHub Actions，完全免费）

```yaml
# .github/workflows/crawler.yml
name: Daily Crawler
on:
  schedule:
    - cron: '0 0 * * *'   # UTC 0点 = 北京时间 8点
  workflow_dispatch:       # 手动触发
jobs:
  crawl:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with: { python-version: '3.11' }
      - run: pip install -r crawler/requirements.txt
      - run: python crawler/run.py
        env:
          DATABASE_URL: ${{ secrets.DATABASE_URL }}
          DEEPSEEK_API_KEY: ${{ secrets.DEEPSEEK_API_KEY }}
      - run: |
          git config user.name "crawler-bot"
          git config user.email "bot@users.noreply.github.com"
          git add crawler/logs/ || true
          git commit -m "chore: daily crawler log" || true
          git push
```

### 9.6 域名与备案
- 免费方案：先用 `xxx.vercel.app` + `xxx.onrender.com` 子域名
- 想要自定义域名：买 `.top` / `.xyz` 域名（~10元/年），海外服务器免备案
- 国内访问 + 自定义域名 → 需备案（学生个人可办，1-3 周）

## 11. 合规与法律要点

### 11.1 数据来源合规
- GitHub 开源仓库遵循其 License（多数 MIT/unlicense，可引用）
- 企业官网数据仅展示摘要 + 跳转原链接，不全文复制
- **不爬** BOSS/智联/前程无忧（用户协议禁止 + 反爬）
- 爬虫遵守 `robots.txt`，控制频率（每站点 ≤1 req/s）

### 11.2 用户数据保护
- 必备：用户协议 + 隐私政策页面
- 密码 bcrypt 哈希，绝不存明文
- IP 哈希存储（不存原始 IP）
- 提供账号注销 + 数据导出功能（符合个保法）
- 简历数据加密存储，用户可删除

### 11.3 平台合规
- 用户协议明确"信息来源于公开渠道，仅供参考"
- 岗位详情页标注数据来源 + 原文链接
- 不保证信息时效性声明
- 提供"信息有误反馈"通道

### 11.4 AI 内容合规
- AI 生成的简历/分析标注"AI 生成，请人工校对"
- 接入大模型的内容审核 API（DeepSeek/智谱自带）
